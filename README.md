# Stix N Vibes shop app

The Stix N Vibes shop (shop.stixnvibes.com) as an Android app. React Native +
Expo (SDK 58) + expo-router + TypeScript.

The app holds **no keys or secrets**. It reads the catalogue and places orders
through the shop's public API (`/api/app/shop`, `/api/app/order/…`,
`/api/order`, `/api/coupon`, `/api/upload`, `/api/custom`, `/api/pay`,
`/api/events`). Products, prices, offers, coupons, colleges, stalls, blog and
library are all managed in the shop admin as before.

## What's in it

- **Shop**: home, browse by type / collection, search, product pages with
  options, cart with live offers, coupon codes and nudges, checkout
  (delivery or stall pickup), order page with status and tracking.
- **Pay in one tap**: the order page opens Google Pay, PhonePe, Paytm or BHIM
  directly with the amount and order ref filled in, or "Pay online" through
  YouPI when it's up. QR and UPI ID as backup. The app polls the order and
  shows "Paid" once the shop sees the money.
- **Personalisation**
  - Personalised products: text, links and photos (camera or gallery) with
    a live preview card.
  - Build a sticker pack, and "print your own design" requests.
  - A personal shop on the phone, no login: college + vibes picked on first
    open drive "Picked for you", wishlist, recently viewed, My orders with
    live status, saved checkout details.
- **Works at stalls with no signal**: the last catalogue is kept on the phone.
- **Links open in the app**: stall QR links (`?src=…&code=…`) credit the
  stall and apply the code; `shop.stixnvibes.com/shop/…`, `/order/…`, `/c/…`
  links offer to open in the app.

## Getting the APK

Every push builds an APK on GitHub Actions (free, no EAS):
**Actions → Android APK → latest run → Artifacts → stixnvibes-shop-apk**.
Unzip, copy the `.apk` to the phone, open it and allow "install unknown apps".

To build against a test shop (e.g. a Netlify deploy preview), run the
workflow by hand (**Run workflow**) and paste the preview URL in `shop_url`.

### Signing (do this once before giving the app to customers)

Without a signing key, CI signs with a debug key: fine for testing, but
customers couldn't update to a properly signed version later. Make a key
on your own computer (needs Java's `keytool`), and keep the file and
passwords safe; losing them means a new app listing:

```sh
keytool -genkeypair -v -storetype PKCS12 -keystore stix-release.keystore \
  -alias stixnvibes -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 stix-release.keystore   # macOS: base64 -i stix-release.keystore
```

Then in GitHub: **Settings → Secrets and variables → Actions → New repository
secret**, add `STIX_KEYSTORE_BASE64` (the base64 text), `STIX_KEYSTORE_PASSWORD`,
`STIX_KEY_ALIAS` (`stixnvibes`) and `STIX_KEY_PASSWORD`.

Tag a release (`git tag v1.0.0 && git push --tags`) to attach the APK to a
GitHub release page you can share.

## Developing

```sh
npm ci
npm run check        # typecheck + unit tests
npx expo start       # Expo dev server; press w for web, or use a dev build
```

Point the app at another shop with `EXPO_PUBLIC_SHOP_URL`, e.g. a local
`next dev` of stixnvibes-nv (it runs on demo data).

`src/lib/{pricing,money,phone,instagram,markdown,types}.ts` are copies of the
shop's files so cart totals match what the server charges. After the shop
changes one: `npm run sync-shop-lib -- ../stixnvibes-nv && npm test`.

Native folders (`android/`, `ios/`) are generated by `expo prebuild` and not
committed; configure them through `app.json` and `plugins/`.
